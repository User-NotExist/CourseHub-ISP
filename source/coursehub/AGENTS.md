## Project-specific agent guide (CourseHub)

- Framework & versions: Next.js 16 (app router), React 19, TypeScript, Tailwind CSS v4. Confirm docs under `node_modules/next/dist/docs/` for framework-specific behavior.

- Project layout: source files live in `src/` — primary areas: `src/app` (routes/layouts/pages), `src/components` (UI and pages' components), `src/lib` (mock data & utilities), and `public`.

- Server vs Client components: The app uses the Next.js app directory; many files are client components (they contain a "use client" directive). Preserve "use client" when editing UI that uses browser-only APIs or hooks. Avoid moving client-only logic into server components.

- Routing & APIs: App routes live under `src/app` (e.g., `api_auth`, `api_course`). Follow the app-router conventions (route handlers inside the app dir) instead of legacy `pages/api` patterns.

- Styling & design system: Tailwind is used with shadcn/base-ui primitives in `src/components/ui`. Global styles live at `src/app/globals.css`. Keep Tailwind classes and utility-first patterns intact.

- Mock data & utilities: `src/lib/mock_data.tsx` and `src/lib/utils.ts` provide sample data and helpers. Use them for local development and tests; do not leak real secrets into these files.

- Dev & containerization: Dev script runs `next dev -H 0.0.0.0` (exposed host). A `Dockerfile` exists for container builds — respect host/port flags for containerized testing.

- Generated/ephemeral files: `.next`, `node_modules`, and the top block in this file may be regenerated by `next dev`. Do not remove the BEGIN/END nextjs block; committing it avoids uncommitted diffs.

- Environment & secrets: `.env` is present. Never print or commit secret values. Agents should assume sensitive values live there or in the deployment environment.

- Linting & build checks: Use `npm run lint` (eslint) and `npm run build` (next build) to validate changes. Update types and run TypeScript checks when editing TS files.

- Where to look first for context: `src/app` (routing & layouts), `src/components` (UI), `src/lib` (data/utilities), `next.config.ts`, `package.json`, and `Dockerfile`.

- Verification steps for changes: run dev, exercise pages under `/`, exercise course pages (`/courses`), and test API routes under `/api_*`. Run build and lint before proposing PRs.
